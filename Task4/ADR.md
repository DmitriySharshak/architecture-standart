### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
|NFR-1|Задержка обновления ставок ≤ 30 сек, для наличия самой актуальной иформации при консультировании|
|NFR-2|Доступность API ставок 99.5% даже при временной недоступности API|
|NFR-3|Кэширование ставок на 5 минут в системе кол-центра, для снижения нагрузки на сервис ставок и для повышения доступности|
|NFR-4|Частота обновления файлов каждые 15 минут |
|NFR-5|Формат файла CSV с шифрованием для безопасносной передачи|

### <a name="_qmphm5d6rvi3"></a>**Решение**

[Диаграмма контекста](out/C4_Context.png) \n
[Диаграмма контейнеров](out/C4_Container.png)

Логика принятия решения:
1. Поддержка совместимости через SFTP + файлы для партнёрского кол-центра
2. Предложено кеширование на двух уровнях. 
   1. InMemory уровне Сервиса ставок (краткосрочное, на 30 сек)
   2. В персистентном хранилище системы кол центра (5 мин)
3. Предложено шифрование файлов для передачи в систему партнера
4. Система кол-центра может работать со ставками даже при недоступности API  
5. Передача файлов настроена по расписанию

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Разработка единого API как единый механизм получения ставок, но сейчас это не допустимо так как внешняя система не может делать обращения к API

**Недостатки, ограничения, риски**
К недостаткам можно отнести:
1. Задержка доставки данных до партнёра до 15 минут
2. Не передается дельта по ставкам. Каждый раз выгружается все

**Список верхнеуровневых задач в разрезе систем**
Сервис ставок:
  TASK-1. Реализация API
  TASK-2. Функция кеширования
  TASK-3. Функция публикации в брокер сообщений
  
Файлов процессор:
  TASK-1. Функция формирования CSV файла со ставками
  TASK-2. Функция шифрования 
  TASK-3. Функция загрузки файла на SFTP сервер по расписанию

Система кол-центра:
